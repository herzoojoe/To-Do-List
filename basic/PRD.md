# My Tasks (basic 버전) PRD

> 이 문서는 `To-Do List` 프로젝트의 `basic/` 폴더에 담긴 **My Tasks** 앱을 다룹니다. 루트의 To-Do List 앱과는 별개의 코드베이스이며, 기본 구조부터 단계적으로 기능을 쌓아 올린 버전입니다. 루트 버전 PRD는 [../PRD.md](../PRD.md) 참고.

## 1. 개요

### 1.1 제품 목적
매일 10~20개 수준의 할 일을 관리하는 개인용 To-Do 앱. 설치·회원가입 없이 브라우저에서 바로 사용하고, 새로고침해도 데이터가 유지되는 가벼운 도구.

### 1.2 대상 사용자
- 본인(1인 사용) 전용
- 업무/개인/공부로 할 일을 구분하고, 카테고리별 진행 현황을 한눈에 보고 싶은 사용자

### 1.3 핵심 가치
- **빠른 진입**: 로컬 정적 서버만 띄우면 바로 사용 가능
- **데이터 유지**: 새로고침해도 목록·필터·테마가 사라지지 않음
- **가벼움**: 프레임워크·빌드 과정 없는 순수 HTML/CSS/JS

## 2. 범위

### 2.1 In Scope (구현 완료)
| 기능 | 설명 |
|---|---|
| 할 일 추가 | 입력창 + 카테고리 드롭다운 + 추가 버튼, Enter 키 또는 버튼 클릭으로 추가 |
| 할 일 삭제 | 항목별 × 버튼으로 즉시 삭제 |
| 완료 체크 | 체크박스로 완료/미완료 토글, 완료 시 취소선 처리 |
| 완료 항목 자동 정렬 | 완료된 항목은 자동으로 목록 하단으로 이동 |
| 카테고리 분류 | 업무(work) / 개인(personal) / 공부(study), 항목별 색상 태그로 구분 |
| 카테고리 필터 | 상단 필터 버튼(전체/업무/개인/공부), 선택 상태는 `localStorage`에 저장되어 새로고침 후에도 유지 |
| 진행률 대시보드 | 전체 진행률(완료/전체, %)과 카테고리별 진행률 바를 함께 표시, 현재 필터와 무관하게 항상 전체 데이터 기준 |
| 생성 시간 표시 | 항목 추가 시각을 "방금 전 / N분 전 / N시간 전 / N일 전"으로 표시, 60초마다 자동 갱신 |
| 다크 모드 | 시스템 설정(`prefers-color-scheme`) 자동 감지 + 우측 상단 토글 버튼(🌙/☀️ SVG 아이콘), 선택값은 `localStorage`에 저장 |
| 데이터 영속성 | 할 일 목록·필터·테마 모두 `localStorage`에 저장되어 새로고침·재접속 시 복원 |
| 접근성 | 입력창/선택창/체크박스/삭제 버튼에 `aria-label`, 키보드 포커스 시 아웃라인 표시 |
| 반응형 | 480px 이하 모바일 화면에서 입력 폼과 대시보드가 자동으로 줄바꿈되어 재배치 |

### 2.2 Out of Scope
- 할 일 텍스트/카테고리 **수정**(인라인 편집) 기능 — 루트 버전에는 있으나 이 버전은 추가/삭제/완료 토글만 지원
- 회원가입/로그인, 서버 연동, 클라우드 동기화
- 여러 기기 간 데이터 공유
- 날짜별 할 일 분리, 캘린더 뷰
- 알림/리마인더, 협업(공유·댓글) 기능
- 서브태스크, 태그, 우선순위, 마감일

## 3. 사용자 스토리

1. 사용자로서, 할 일을 카테고리와 함께 빠르게 추가하고 싶다.
2. 사용자로서, 더 이상 필요 없는 항목을 × 버튼으로 즉시 지우고 싶다.
3. 사용자로서, 완료한 항목을 체크하면 자동으로 목록 아래로 내려가 남은 일에 집중하고 싶다.
4. 사용자로서, 업무/개인/공부별로 필터링해서 보고 싶다.
5. 사용자로서, 전체 진행률뿐 아니라 카테고리별 진행률도 한눈에 보고 싶다.
6. 사용자로서, 각 할 일을 언제 추가했는지 대략적인 시간으로 확인하고 싶다.
7. 사용자로서, 야간에는 다크 모드로 편하게 보고, 그 설정이 다음 접속 때도 유지되길 원한다.
8. 사용자로서, 새로고침하거나 다시 접속해도 목록·필터·테마가 그대로 남아있길 원한다.

## 4. 기능 상세 요구사항

### 4.1 할 일 추가
- 텍스트 입력창(최대 200자) + 카테고리 드롭다운(업무/개인/공부, 기본값 업무) + 추가 버튼
- Enter 키와 버튼 클릭 모두 지원
- 빈 텍스트(공백만 입력 포함)는 추가되지 않음
- 새 항목은 목록 최상단에 추가됨

### 4.2 할 일 삭제
- 항목 우측의 × 버튼 클릭 시 별도 확인 없이 즉시 삭제

### 4.3 완료 체크 및 정렬
- 체크박스로 완료/미완료 토글
- 완료 항목은 취소선 + 흐린 색상으로 표시
- 목록 렌더링 시 완료 항목은 항상 미완료 항목보다 아래에 위치하도록 정렬

### 4.4 카테고리 분류 및 필터
- 카테고리: 업무(`work`, `#4A90E2`) / 개인(`personal`, `#27AE60`) / 공부(`study`, `#8E44AD`)
- 각 항목에 카테고리 색상 태그 표시
- 상단 필터 버튼(전체/업무/개인/공부)으로 목록 필터링, 선택된 필터는 강조 표시
- 필터 상태는 `localStorage`에 저장되어 새로고침 후에도 유지

### 4.5 진행률 대시보드
- 전체 진행률: "완료 N / 전체 M" + 퍼센트 + 진행률 바
- 카테고리별 진행률: 업무/개인/공부 각각의 완료 수/전체 수와 진행률 바 (해당 카테고리 색상 사용)
- 대시보드는 현재 필터 선택과 무관하게 항상 전체 데이터를 기준으로 계산

### 4.6 생성 시간 표시
- 각 항목에 상대 시간 표시: 1분 미만 "방금 전", 1시간 미만 "N분 전", 하루 미만 "N시간 전", 7일 미만 "N일 전", 그 이상은 "M월 D일" 형식
- 화면이 열려 있는 동안 60초마다 전체 재렌더링 없이 시간 텍스트만 갱신

### 4.7 다크 모드
- 저장된 테마가 없으면 시스템 설정(`prefers-color-scheme: dark`)을 기본값으로 사용
- 헤더 우측 토글 버튼(🌙/☀️ SVG)으로 즉시 전환
- 선택한 테마는 `localStorage`에 저장되어 재접속 시에도 유지
- 테마 적용은 페이지 렌더링 전 `<head>` 인라인 스크립트에서 이루어져 깜빡임(FOUC) 없음

### 4.8 데이터 저장 (영속성)
- 모든 추가/삭제/완료 토글/필터 변경/테마 변경 시 `localStorage`에 즉시 저장
- 페이지 로드 시 저장된 데이터를 불러와 렌더링, 없으면 빈 목록·기본 필터("전체")·시스템 테마로 초기화

### 4.9 접근성 및 반응형
- 입력창·카테고리 선택·체크박스·삭제 버튼에 의미 있는 `aria-label` 부여
- 키보드로 포커스 이동 시 각 인터랙티브 요소에 시각적 아웃라인 표시
- 480px 이하 화면에서 입력 폼이 세로로 재배치되고 대시보드 레이아웃도 좁은 화면에 맞게 조정

## 5. 데이터 모델

```js
// localStorage key: "basic_todos"
[
  {
    id: "uuid-or-timestamp",
    text: "React 강의 듣기",
    completed: false,
    category: "study", // "work" | "personal" | "study"
    createdAt: "2026-08-22T09:00:00.000Z"
  }
]

// localStorage key: "basic_filter"
"all" // "all" | "work" | "personal" | "study"

// localStorage key: "basic_theme"
"light" // "light" | "dark" — 없으면 시스템 설정(prefers-color-scheme)을 따름
```

> 루트 To-Do List 앱과 같은 origin에서 서비스되더라도 `basic_` 접두사를 사용한 별도 키를 쓰기 때문에 `localStorage` 데이터가 서로 섞이지 않는다.

## 6. 기술 요구사항

- **언어/스택**: 순수 HTML + CSS + Vanilla JavaScript (프레임워크, 빌드 도구 없음)
- **실행 방식**: 로컬 정적 서버로 서빙해서 실행 (권장) — `python -m http.server 8080` 등으로 프로젝트 루트에서 구동 후 `http://localhost:8080/basic/` 접속
  - ⚠️ `basic/index.html`을 `file://`로 직접 여는 방식은 지양한다. CSS/JS 로드나 `localStorage` 접근이 제한될 수 있음
- **저장소**: `localStorage` (브라우저 내장, 별도 백엔드 불필요)
- **호환성**: 최신 Chrome/Edge 기준
- **반응형**: 데스크톱 우선, 480px 이하 모바일 화면까지 대응

---

## 7. 비기능 요구사항

- 할 일 10~20개 수준에서 지연 없이 즉시 반응
- 코드 구조는 3개 파일(HTML/CSS/JS)로 단순하게 유지
- 별도 인증/보안 요구사항 없음 (개인 로컬 데이터)
- 텍스트 렌더링은 `textContent` 기반으로 처리해 XSS 위험 없음

## 9. 성공 기준 (Acceptance Criteria)

- [x] 할 일을 추가하면 즉시 목록에 나타난다
- [x] × 버튼 클릭 시 항목이 목록에서 사라진다
- [x] 체크박스 클릭 시 완료 상태가 시각적으로 구분되고 목록 하단으로 이동한다
- [x] 카테고리 필터를 클릭하면 해당 카테고리 항목만 보인다
- [x] 필터 상태가 새로고침 후에도 유지된다
- [x] 대시보드의 전체·카테고리별 진행률이 실제 데이터와 정확히 일치한다
- [x] 각 항목의 생성 시간이 상대 시간으로 표시되고 자동 갱신된다
- [x] 다크 모드 토글 클릭 시 즉시 테마가 전환되고, 새로고침 후에도 유지된다
- [x] 로컬 서버 구동만으로(`file://` 아님) 빌드 없이 정상 동작한다
- [x] 480px 이하 모바일 화면에서도 레이아웃이 깨지지 않는다

- 우선순위, 마감일 설정
- 데이터 내보내기/가져오기(JSON export/import)
